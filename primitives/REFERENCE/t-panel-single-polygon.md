# TPanelSinglePolygon

> 返回 [REFERENCE 类型索引](../../documents/REFERENCE.md)

## 定义

面板单多边形

⚠️ **本类型不是图元、不占任何一行数据**——它是 `TPanelPoly.ploys` 与
`TPanelString.path` 这两个字段**内部元素**的类型。

**定义**：一条**首尾重合、不间断的线**所描述的区域。首尾不重合会被**自动闭合**。

【设计动机】与 PCB 侧同一套思路：仿造 SVG 的 `path`，但去掉相对坐标等用不到的能力，
换一种**更容易解析**的表达。

【线格式】**首元素是形态标记**，决定这一条怎么解释；解析端也只在
「外层长度为 1」时按首元素分派：
- `'M'` —— 显式书写起点的指令形态：
  `["M", x1, -y1, "A"|"CA", rx, ry, angle, large, sweep, x2, -y2]`
  （第 4 个 token 为 `'A'` 表示**两点弧**、`'CA'` 表示**中心弧**）
- `'R'` —— 矩形：`["R", x, y, width, height, rx, ry, rot, isCCW]`，共 **9 个元素**。
  ⚠️ **3.0 里只有 `rx` / `ry` 有效**：写端**恒写** `['R', 0, 0, 1, 1, rx, ry, 0, 0]`，
  读端也只取 rx/ry —— 其余槽（x/y/width/height/rot/isCCW）是 2.0 的位置化遗留，
  **图元的位置、尺寸、旋转全在 `matrix` 里**，不要照着这些槽去还原几何。
- `'ELLIPSE'` —— 椭圆：`["ELLIPSE", cx, cy, rx, ry, rot, isCCW]`。
  同 `'R'`：3.0 写端**恒写** `['ELLIPSE', 0, 0, 1, 1, 0, 0]`，读端不读 poly 的任何槽，
  几何同样由 `matrix` 承载。两种形态都与其它模式**互斥**。
- **既非 `'R'` 也非 `'ELLIPSE'` / `'M'`** —— 此时**首元素才是坐标**，
  即**起始的 "M" 已被省略**：前两个数字为起点坐标，其后是「指令名 + 该指令参数」
  的重复序列，参数个数由指令决定。例：
  `[237.402, 1864.961, "A", 227.46, 227.46, 0, 1, 1, 529.921, 1527.953]`
  等价于 `M 237.402 1864.961 A 227.46 227.46 0 1 1 529.921 1527.953`。

**写端只产出绝对坐标指令**（`M` / `L` / `A` / `CA` / `C` / `Q` / `Z`）；
⚠️ 这是**写盘约定**，不是解析端的限制——通用路径解析器本身也认相对指令。
其中 `'A'` 的 7 个参数按 SVG 顺序为 `rx ry rot large sweep endX endY`
（代码里第 5 参叫 `sweep`，即 SVG 的 sweep-flag）；
`'CA'`（中心弧）**只在这一形态的第 4 个 token 位置被识别**。

坐标与长度单位同面板域：**0.01 inch**（见 `TPanelBase`）。
