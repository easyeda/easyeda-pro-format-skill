# TInstanceDocUuid

> 返回 [REFERENCE 类型索引](../../documents/REFERENCE.md)

## 定义

文档 uuid —— **实例属性文档**

⚠️ **本类型不是格式图元**（本目录都是这类 id 说明），它**不占任何一行数据**，也**没有字段用它当类型**。

含 `_$` 与 `~` **两级分隔符**。它其实是**从顶层原理图走到目标实例页的一条路径**：
每向下进一层就追加 `_$<Sheet 的 uuid>`，这一层若是块符号、再跟 `~<块符号的 uuid>`。

## 各段分别是什么、从哪来

| 位置 | 是什么 | 值从哪来 |
| ---- | ------ | -------- |
| **第 1 段** | 层次图的**顶层原理图** | 根部那个 SCH 文档的 [TDocUuid](./t-doc-uuid.md) |
| **中间的每对 `_$X~Y`** | 一路经过的 **Sheet** + 它里面的**块符号** | `X` = 那层图页文档的 uuid；`Y` = 该块符号**图元**的 id |
| **最后一段 `_$X`** | **目标实例页所在的 Sheet** —— **只到 Sheet 为止**，不再跟 `~` | 同上，那层图页文档的 uuid |

真机样本：`"3c810a1544706db5_$30968987fbc1647d~ie0_$bbbca101b360e299"`
⇒ 顶层原理图 `3c810a15…` → Sheet `30968987…` 里的块符号 `ie0` → 落在 Sheet `bbbca101…`。

## 两点别踩

- 与**宿主内嵌文档**那种 uuid 的区别就在 `_$`：**只有单个 `_` 的**是宿主内嵌文档；
- UI 的「实例页 tabId」在这串后面**可能还缀着 `@<工程 uuid>`**（模板页 tabId 则是
  `<sheetUuid>@<工程 uuid>`）。**真机样本的文档头 uuid 里没有该后缀**——
  解析时以 `_$` / `~` 为准，**不要假设 `@` 一定在、也不要假设一定不在**
  （那个后缀跟的是**工程 uuid**，与实例路径里 `_$` / `~` 的分段不是一回事）。
